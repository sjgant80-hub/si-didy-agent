POST 2 · THE TUTOR (the soul · day 4)
────────────────────────────────────────────────────────
audience: people who are skeptical of "AI tools" · people who care about the human side
hook: the 5-phase Jungian arc
visual: screenshot of the tutor showing the phase chip + a real first conversation

▼ COPY ▼
Every "AI productivity tool" built for the laid off gets one thing catastrophically wrong.

They skip phase 1.

They open with "let's set up your CRM." "Pick your niche." "What's your USP?"

This is wrong. Brutally wrong. And it's why none of them stick.

The first phase of post-redundancy life is THE WOUND. The identity you had — employee, member of the team, valued contributor — has died. That is grief. Grief has its own clock and its own work to do.

The tools that rush past phase 1 are taking somebody in shock and trying to sell them a five-tier marketing funnel.

When I built ExitEngine I baked the 5 phases into the tutor:

Phase 1 · the wound. Sit with it. Don't make irreversible decisions this week. Don't post publicly. Don't borrow against your future. Sleep.

Phase 2 · the shadow. The skills belonged to you, not the company. They kept the Salesforce licence. You kept the twelve years.

Phase 3 · the rebirth. Action erodes grief. Set up the CRM. Pick a rate. Send the first outreach.

Phase 4 · the integration. You are not an ex-employee anymore. You're a business owner. The tutor shifts from teaching to coaching.

Phase 5 · the sovereign. You don't need the tutor anymore. Take it offline. Run from USB. The internet is now optional.

Every phase has its own tone. Phase 1 is calm. Phase 3 is energetic. Phase 5 is quiet and complete.

The tutor uses an LLM if you paste a key. Without one, it falls back to pre-written 5-phase mode. Both work. The lesson is the structure, not the model.

Built it because I needed it. Shipping it because someone reading this needs it.

Free. MIT. sjgant80-hub.github.io/exitengine/tutor.html

POST 3 · THE BUILDERS (architecture · day 8)
────────────────────────────────────────────────────────
audience: developers · open-source supporters · founders who care about UX of grief
hook: how do you build a sovereign business OS for someone in shock

▼ COPY ▼
Building ExitEngine taught me something about UX of distress.

When a user is in shock — laid off, evicted, broken up with, bereaved — the design rules invert.

What you normally do:

· clever onboarding with progressive disclosure
· bright accent colours to hold attention
· animation to delight
· dense information architecture

What you should do:

· one decision at a time · everything else hidden
· calm, low-contrast colour for most of the UI, warm accent only on human moments
· no animation that competes with internal motion
· big touch targets · because fingers shake

ExitEngine is built on these inverted rules.

Architecture choices:

1. Single GitHub repo · the fork IS the install. No package manager, no installer, no terminal. You click Fork.

2. One config file drives the whole OS. The user enters their name in one place. Every invoice, every proposal, every email signature updates. Less cognitive load.

3. Vanilla JS · no framework · no build step. Every file is readable in an evening. There is no abstraction layer hiding the work. If anyone forks and wants to modify, they can.

4. BroadcastChannel('fall-signal') for cross-tool integration. No backend. No server. Tools communicate by browser-native message passing. Loose coupling. Removing any tool doesn't break the others.

5. localStorage per-tool keys. State persists, no signup, no sync server. If the user wants to move devices, they download config.json and the data exports as JSON.

6. AI cascade with graceful fallback. With an API key, the tutor is conversational. Without, it's a pre-written 5-phase flow. T0 always works. The model is enhancement, not requirement.

7. EU AI Act Article 12 audit shim baked in. Regulator opens DevTools, sees the SHA-256 chain, satisfied.

8. The download button. The whole repo zips and runs from file://. The internet becomes optional. The sovereignty is real.

The cost of all this: zero monthly fees, zero tracking, zero dependency on any infrastructure I control.

The benefit: when GitHub Pages eventually changes terms (it will), the tool is already on the user's USB stick. When the LLM provider changes pricing (they will), the tutor still works in T0 mode. When I lose interest (I won't), the code is MIT.

If you build for people in distress: invert the rules.

If you build sovereign tools: the simplest architecture wins.

If you know someone laid off: ExitEngine is free, MIT, fork-able. Send them the URL.
